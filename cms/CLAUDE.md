# Mark Hachem Gallery — CMS

Payload 3 (headless CMS + admin) + Next.js 16 frontend in a single project. Replaces the static HTML site at `../mark-hachem-gallery/` once stabilised — the static site stays the source of truth for design while the customer iterates.

## Stack

- **Payload CMS 3.83** — collections, admin UI, local + REST + GraphQL APIs
- **Next.js 16 (Turbopack)** with React 19 — frontend route group + admin route group share one Next app
- **SQLite** via `@payloadcms/db-sqlite` — file at `payload.db` (gitignored)
- **Local media storage** in `./media/` (gitignored). Sharp generates `thumbnail`, `card`, `hero` sizes for images. PDFs allowed.
- **Lexical** for richtext (default editor)
- **next/font/google** loads Cormorant Garamond + Outfit at build time — no Google Fonts CDN at runtime

## Daily workflow

```bash
./cms.sh start              # background dev server, waits until /admin responds
./cms.sh stop | restart | status | logs
PORT=3001 ./cms.sh start    # override port

npm run seed                # wipes Artists/Exhibitions/Media + reseeds from ../mark-hachem-gallery/ HTML
                            # creates admin user if missing; STOP server first (SQLite locking)
npm run generate:types      # regenerate src/payload-types.ts (after schema changes)
npm run generate:importmap  # regenerate admin component import map (after adding/removing fields with custom components)
```

**Re-seed cycle:** `./cms.sh stop && npm run seed && ./cms.sh start`.

## SEO infrastructure (already in place)

- Per-page `<title>` + `description` via Next.js Metadata API; root layout sets `metadataBase` from `NEXT_PUBLIC_SITE_URL`, default canonical, OG, Twitter, robots
- Per-page `alternates.canonical` overrides
- JSON-LD: **ArtGallery** on home, **Person + BreadcrumbList** on artist detail, **CollectionPage + BreadcrumbList** on `/artists`, **BreadcrumbList** on `/exhibitions`
- Favicon wired via `metadata.icons`
- Dynamic `sitemap.ts` and `robots.ts`
- `NEXT_PUBLIC_SITE_URL` in `.env` — set to `https://www.markhachem.com` before deploy

## Conventions / gotchas

- **After adding a collection/global field** that uses a custom admin component (richText counts), run `npm run generate:importmap` or the admin throws "PayloadComponent not found in importMap". The dev server doesn't auto-run it.
- **After schema changes** that affect `payload-types.ts`, run `npm run generate:types` — the frontend pages use those types via `lib/media.ts`.
- **Schema migrations on existing data**: Payload's SQLite adapter uses dev "push" mode. Adding a column to a populated table can fail mid-migration ("no such column: X" during `INSERT INTO __new_X SELECT …`). Safest path while iterating: `./cms.sh stop && rm payload.db payload.db-journal && ./cms.sh start && npm run seed`.
- **Stop the dev server before seeding** — SQLite write locks. The seed bypasses Payload access control via the local API; no auth needed.
- **Plain `<img>` over `next/image`** — keeps things simple in dev and avoids `remotePatterns` config for the external strip URLs. Migrate to `next/image` only when prepping production.
- **Nav auto-derives variant from pathname**: `/` → `hero` (transparent over hero, scroll listener turns it solid), every other route → `solid`. Don't pass `variant` as a prop.
- **Scroll reveals**: any element with `.reveal` (and optional `.reveal-delay-{1..6}`) gets observed by `<ScrollReveal />` mounted once in the root layout.
- **Lexical richtext** stored under `{ root: { children: [...] } }`. The seed builds it manually as plain paragraphs (no inline formatting yet — em/strong tags from source HTML are lost). `<RichText content={…} />` renders it back. `richTextToPlainString()` produces meta-description-friendly snippets.
- **Cmd to run from any cwd**: `./cms.sh` cds to its own directory; npm scripts assume the project root, prefer absolute paths if launching from elsewhere.

## Source of truth & spec

- **Static HTML** at `../mark-hachem-gallery/` is the design source while the customer iterates fast in HTML. Don't modify it from this project.
- **Homepage spec** for the next CMS-side rebuild lives at [docs/website-prd.md](docs/website-prd.md). It enumerates every section, what should be selectable / orderable, and which collections are missing (News, Fairs, plus several Settings/global gaps).
- **Seed source.** `scripts/seed.ts` parses `../mark-hachem-gallery/index.html`, `artists.html`, `exhibitions.html`, and per-artist `artists/{slug}.html` files, uploading images via the local API. Re-runnable; resets content collections each time.

## Project goals

- Move the gallery from static HTML to a CMS-backed site without disrupting the customer's HTML iteration loop. The customer makes design/content edits in HTML; once stable, those changes get reflected in the CMS schema and re-seeded.
- Keep the admin UX simple enough for non-technical editors to manage Artists, Exhibitions, News, Fairs, Settings, and curated homepage selections.
- Production-quality SEO from day one: structured data, sitemap, canonical URLs, OG/Twitter cards, semantic HTML.
- Local-first: SQLite + local media now; production target is Cloudflare Workers + R2 + a managed Postgres (Neon/Hyperdrive) — the schema is portable, the adapters swap.
- Preserve the existing visual design (typography, gold accent, kinetic hero animations, scroll reveals) byte-equivalent — the CSS in `(frontend)/styles.css` is lifted directly from `index.html` and should stay in sync as the customer edits HTML.

## What is *not* yet modelled

See [docs/website-prd.md](docs/website-prd.md) "Gap summary" for the full list. Highlights:
- **News collection** + `/news` routes (the customer added a News section + per-news HTMLs)
- **Fairs collection** (homepage Latest + Art Fairs sections)
- **Homepage global** for curated subsets (featured artists, news, past exhibitions, collection works) and hero copy
- **About global** for philosophy block + milestones
- Per-artist `featuredArtwork` (the home card image differs from the artist-page portrait)
- Settings extensions: multi-phone / multi-address per location, Artnet social, WhatsApp prefilled message, gallery-strip array
